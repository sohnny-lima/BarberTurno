## 7. Cómo revisar (responsable)
**PWA en el navegador (escritorio o el emulador):**
1. Cierre cualquier backend en 8081. Desde `D:\Proyectos\BarberTurno-v2-pwa\frontend`: `pwsh -NoProfile -File tools/revision-conjunta.ps1` (pide la clave de las cuentas ficticias y abre las ventanas; la PWA se registra en el *build* de producción que sirve el jar). Si el jar no está al día: `npm run build` y `..\backend\mvnw.cmd -Pcon-frontend -Dexec.skip=true -DskipTests package` desde `backend\`.
2. En Chrome: menú → «Instalar aplicación» (o el icono de instalar de la barra). Probar: Atrás con un diálogo y con el menú abiertos; DevTools → Application → Service Workers → «Offline»: aparece el aviso y una escritura falla sin quedar pendiente; DevTools → Application → Cache Storage: solo recursos públicos (ningún `/api`); cerrar sesión, entrar con otra cuenta y pulsar Atrás.
3. Cuentas: `cliente`, `encargado`, `multirol`, `personal-cliente`, `plataforma` `@ejemplo.test`.

**APK de prueba en el emulador:**
1. `D:\Android\Sdk\emulator\emulator.exe -avd Medium_Phone_API_36.0` (con ventana; sin ventana añada `-no-window -gpu guest`).
2. `adb install -r D:\Android\barberturno-twa\app-release-signed.apk` y `adb reverse tcp:8081 tcp:8081`.
3. Para regenerarla: `pwsh -File android/generar.ps1` (Bubblewrap en `D:\Android\bubblewrap`; clave de prueba en `D:\Proyectos\BarberTurno\.local\android\`).
4. Esperado hoy: la app se instala y abre Chrome en `https://localhost/` con barra de dirección y sin conexión, porque no hay dominio con HTTPS. La aplicación web se prueba en Chrome del emulador en `http://localhost:8081`.

**Teléfono real (cuando haya dominio):** activar «Depuración USB», `adb install -r …`, abrir la app y comprobar que no aparece la barra de dirección, que los enlaces `https://<dominio>/invitacion/…` abren la app, la descarga del Excel y TalkBack en acceso, reserva y mis citas.
