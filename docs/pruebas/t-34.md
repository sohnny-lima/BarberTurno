## Entorno y ejecución reproducible

Windows 11; JDK Temurin 21.0.8; Node 24.21.0 con fnm y npm 11.19.0;
PostgreSQL 18.0 en localhost:5433. Playwright 1.63.0, axe Playwright 4.13.0;
`@types/node` 24.19.1.
Chromium/Chrome for Testing 153.0.8010.12, revisión Playwright 1243;
Firefox 155.0, revisión 1543. Tipos Node de la serie 24 para comprobar la suite.

Preparación desde `frontend/`, con Node activo según README:

```powershell
npm ci
$env:PLAYWRIGHT_BROWSERS_PATH = Join-Path $PWD 'tmp/navegadores'
New-Item -ItemType Directory -Force tmp/descargas | Out-Null
$env:TEMP = Join-Path $PWD 'tmp/descargas'
$env:TMP = $env:TEMP
npx playwright install chromium firefox
npm run e2e
```

`npm run e2e` ejecuta `e2e/ejecutar.ps1`: fija JDK 21 en su proceso, empaqueta
con `mvnw.cmd -Pcon-frontend clean package -DskipTests` y llama Playwright. El
empaquetado no reemplaza la verificación Maven completa. Para depurar la suite
contra el jar recién empaquetado se usó también `npx playwright test` con
`JAVA_HOME` fijado; cada ejecución conserva la preparación y limpieza.

Cuatro proyectos: Chromium/Firefox a 1440 × 900 y 360 × 800, todos en
`Europe/Madrid`, locale `es-PE`. Un worker, sin reintentos, escenarios en serie;
un jar `dev,demo` nuevo por proyecto, puerto 18034 y reloj de negocio
`2026-09-28T09:00:00-05:00`. `page.clock.setFixedTime` fija únicamente Date del
navegador para conservar el día del escenario; temporizadores y animaciones
siguen funcionando. No se cambia el reloj del sistema ni producción.

El rol de aplicación no tiene permiso para crear bases. La preparación intentó
`CREATE DATABASE barberturno_e2e` y eligió la alternativa autorizada
`barberturno_test`. Vacía las ocho tablas de negocio antes y después de cada
proyecto, conserva Flyway y reinicia identidades. Comprueba conexiones de ambas
bases de prueba y puertos 8080/18034; un archivo exclusivo en `frontend/tmp/`
impide dos suites E2E simultáneas. No se ejecutó `verify` junto con la suite.

Las credenciales ficticias demo/ADMIN y la clave JWT se generan por ejecución
en memoria, solo en el entorno de los procesos. La conexión carga el archivo
local únicamente al entorno; no se escriben estados de sesión ni se muestran
valores. El administrador lo crea el inicializador del backend, sin promoción
SQL. La preparación crea por API una reserva de Ana con Carlos, Barba, el
28/09 a las 09:10: entra en la ventana de atención a las 09:00. También retira
por API K1 de la demo para ensayar el alta de 16–17 del guion; no altera reglas.

No se borraron archivos previos. Playwright, axe y los tipos no necesitaron

## Decisiones menores, deuda y límites

Se usa el entorno Windows local ya acordado; no se introduce servicio externo.
El informe HTML se entrega sin videos, capturas ni trazas pesadas. Los análisis
axe conservan ID, severidad y selectores; no incluyen credenciales.

La matriz prueba las revisiones de Chromium y Firefox descargadas, **no acredita
las dos últimas versiones comerciales de Chrome, Edge y Firefox**. Esa
comprobación manual de RNF-07 y la evaluación con cinco participantes de CP-11
permanecen para el responsable; no se cambian requisitos ni criterios de T-34.
La automatización axe tampoco sustituye la revisión humana de WCAG.

Propuesta para el arquitecto: un `workflow_dispatch` futuro que active JDK 21 y
Node 24, PostgreSQL 18 dedicado, empaquetado `con-frontend`, instalación de ambos
navegadores y `npm run e2e`, con publicación del informe como artefacto y cierre
del jar aun ante fallo. **Solo propuesta:** `.github/` no se modifica y la CI
no ejecuta E2E en este encargo.

Referencias técnicas consultadas: [global setup y teardown](https://playwright.dev/docs/test-global-setup-teardown),
[reloj de Playwright](https://playwright.dev/docs/clock) y
[axe en Playwright](https://playwright.dev/docs/accessibility-testing).

Sin cambios en backend: ningún Javadoc nuevo o modificado y ningún endpoint de
escritura nuevo. Se conservan CSRF, permisos, reglas, contratos y DDL.
Verificados: solo frontend, README, estado/notas de tareas y evidencias T-34;
backend, requisitos, arquitectura, AGENTS, CLAUDE, APF2, `.github/` y
`.gitattributes` intactos respecto de `8529d77`. UTF-8 sin BOM, LF salvo CRLF
en el script PowerShell y `git diff --check` aprobados. Sin lectura de
coordinación, exposición de secretos, datos reales, promoción SQL, push,
remotos, publicación, servicios de pago, etiquetas nuevas, borrado de historial,
cambios de ACL/configuración, delegación ni otras tareas. `T-03-registro`
conservada en `99cb3b5be2da6126d84f39afa868688c93c8011e`.
