## Implementación

- `tools/respaldo.sh`: dump custom fechado en UTC, nombres simples de base, destino externo al repositorio, bloqueo, archivo no vacío, conteos antes/después y publicación; retención estrictamente superior a 14 días solo sobre el patrón de esa base, sin recorrer subdirectorios ni enlaces.
- `tools/restaurar.sh`: inspección previa del dump, creación atómica sin sobrescritura, dueño indicado, restauración transaccional con `--no-owner --role`, comparación exacta por tabla con origen o resumen. Sin borrado automático de bases, también ante errores.
- `tools/respaldo-comun.sh`: resolución de `PG_BIN`, validación y resumen determinista con conteos exactos en transacción repeatable read. Identificadores en hexadecimal para soportar separadores en nombres de tablas.
- `tools/verificar-respaldo.sh`: pruebas de retención/errores con binarios ficticios, sin PostgreSQL.
- `tools/ensayar-recuperacion.ps1`: ensayo reproducible, contraseñas exclusivamente en entorno, rechazo de destino previo, cronometraje y limpieza limitada a sus artefactos, restauración del entorno.
- `.gitignore`: únicamente exclusión `*.dump`. Guía `recuperacion.md`, sección de copias de `despliegue.md`, enlace/comandos en README y registro en tareas.

No se modificó Java, frontend, API, DDL, reglas ni seguridad. No se añadieron endpoints ni Javadoc: no hay API Java nueva/modificada. `verify` conserva la comprobación estricta existente.

```text

```

La aserción siguiente exigía un enlace simbólico, pero `ln -s` de Git Bash generó una copia en este entorno. Se sustituyó esa fixture por un directorio con el patrón de dump, conservado por `-type f`; la implementación mantiene la exclusión de enlaces. Segundo resultado 28/28; se amplió la suite a 33/33 con cambio del origen, igualdad de sumas con tablas distintas y fallo dentro de la restauración. No hubo otros fallos inesperados del ensayo.

Decisiones menores: nombres simples ASCII de base/rol de hasta 63 caracteres para evitar rutas/cadenas de conexión; utilidades GNU en shell POSIX; UTC para nombres; resumen adjunto; roles de creación/restauración separados mediante variables de entorno; base fallida conservada para diagnóstico. La base nueva revoca CONNECT/TEMPORARY de PUBLIC y concede CONNECT al dueño, siguiendo despliegue; no cambia privilegios de bases existentes. El mantenimiento evita divergencias entre la instantánea de dump y los conteos separados; no se pretende comparar el contenido completo de las filas con estos conteos.

Hallazgos no bloqueantes para el arquitecto: la introducción de `docs/despliegue.md` todavía menciona PostgreSQL 18.0/T-38 pendiente; queda fuera de su sección autorizada de copias y no se cambia. El origen concreto del encargo es `barberturno_demo_t32`, más preciso que `demo` del plan. El RPO operativo requiere instalar/vigilar las tareas en el proveedor pendiente; la resiliencia ante pérdida del disco exige que el responsable decida una segunda ubicación protegida.
