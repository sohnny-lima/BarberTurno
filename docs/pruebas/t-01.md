El SQL usa `ON_ERROR_STOP`, comprueba PostgreSQL 18 y el puerto 5433 antes de escribir, valida los objetos existentes, crea únicamente los faltantes y solicita la contraseña mediante `\password` solo si falta. No contiene contraseñas ni instrucciones de borrado o de cambio de dueño. Una base existente con otro propietario o un rol con permisos incompatibles produce un error para revisión, conservando los objetos. Esta revisión estática no sustituye las dos ejecuciones exigidas.

Para completar el criterio pendiente, configure la autenticación administrativa fuera del repositorio (por ejemplo `.local/pgpass.conf`, ignorado) y ejecute en una terminal, dos veces:

```powershell
& 'C:\Program Files\PostgreSQL\18\bin\psql.exe' -X -h localhost -p 5433 -U postgres -d postgres -f tools/db-local.sql
```

En la primera ejecución, si falta la contraseña del rol de aplicación, introdúzcala cuando `\password` la solicite y consérvela localmente como `BT_DB_PASSWORD`. Compruebe que ambas ejecuciones terminan con código 0 y muestran las dos bases con propietario `barberturno`. No cambie las contraseñas o propietarios existentes para forzar la comprobación.
