Backend: `ReservaService` y `CrearReservaDto` habilitan RF-18 solo para ADMIN con `clienteId` obligatorio. `UsuarioAdminController/Service` y DTO: búsqueda literal por fragmento de nombre/correo sin distinguir mayúsculas, rol/paginación e inactivos; respuesta sin hash, versión de token ni bloqueo. Restablecimiento con SecureRandom: doce caracteres ASCII, letra y dígito garantizados, BCrypt, cambio obligatorio, desbloqueo de intentos fallidos y revocación inmediata. Respuesta no-store y `PasswordTemporalDto.toString()` oculta la credencial. Estado sin borrado: desactivar revoca sesiones, reactivar no las resucita, mismo estado es idempotente; rechaza autodesactivación y ausencia del último ADMIN.

**Clave para registrar como DA: `pg_advisory_xact_lock(313131)`**, propia de gestión del acceso RF-19 y distinta de `141414` del cupo de barberos. Se toma antes de filas y conteo de ADMIN activos; después se revalida al actor. Diez repeticiones HTTP concurrentes con transacciones reales: dos ADMIN se desactivan mutuamente, exactamente una 200 y otra rechazada, siempre un ADMIN activo. No se cambia el DDL ni el protocolo de disponibilidad.

Frontend: `core/api/usuarios-api` y modelos espejo; ruta lazy `/admin/usuarios`, búsqueda/filtro/paginación, estados confirmados y diálogo compartido `PasswordTemporalDialogo` con Copiar y `disableClose: true`. Temporal efímera, entregada una sola vez, sin filas/señales/storage/logs ni capturas. Selector compartido `shared/selector-cliente` con espera de 250 ms, cancelación de consultas y resultados/errores; paso Cliente previo para ADMIN en `/reservar`, cliente visible en resumen y `clienteId` enviado. No se calculan reglas de negocio en TypeScript. README explica acceso y verificador reproducible.

Recuperación local de cookie revocada: `SesionService.login` intercepta exclusivamente 401 con código NO_AUTENTICADO, ejecuta logout público con CSRF y repite el login **una sola vez**. CREDENCIALES_INVALIDAS y el fallo del segundo intento se propagan; no hay bucle ni conversión de 401 en éxito. El interceptor deja llegar ese error al servicio y conserva la redirección de 401 de rutas protegidas. Tres regresiones Vitest. DA-22/T-45 resolverán el backend y revisarán este rodeo; no se modifica el resolver en T-31.
