## Incidencias resueltas y comprobaciones de entrega

- El ejecutor aislado continúa fallando al crear procesos (`setup refresh had errors`). Se usó la escalación aceptada para leer, descargar, editar y verificar; no se cambió la propiedad de Git ni el diseño.
- La primera ejecución de verify corrió 42 pruebas y falló solo en health: Boot 4.1 activa por defecto los grupos liveness/readiness, dando `{"groups":["liveness","readiness"],"status":"UP"}`. Se configuró `management.endpoint.health.probes.enabled=false`; la misma prueba exigente pasa con el JSON requerido.
- PowerShell recibió el cuerpo público de Actuator como `Byte[]` por su tipo MIME. Se decodificó como UTF-8 para la comprobación HTTP; el backend ya devolvía correctamente el JSON.
- Los logs de Start-Process permanecieron bloqueados durante el arranque; se revisaron tras detener el proceso. Los siete logs de T-02 no contienen valores de los secretos locales ni `Using generated security password:`.
- Flyway se inicia sin migraciones todavía y prepara su historial vacío; el esquema de negocio se implementará en T-06. No se alteraron ni borraron datos de negocio.
- `mvnw` mantiene LF y modo Git 100755; `mvnw.cmd` tiene CRLF en el árbol de trabajo y LF normalizado en el índice. El resto de los archivos nuevos son UTF-8/LF.
- `git diff --check` se ejecuta antes de cada commit. Un espacio residual del editor XML se corrigió antes del primer commit.
- Credenciales, `.local/`, `target/` y reportes generados permanecen ignorados. La plantilla `tools/barberturno.env.example` contiene marcadores y datos ficticios.
- APF2 y los documentos de requisitos/arquitectura se conservan; T-03 y T-38 continúan pendientes.
